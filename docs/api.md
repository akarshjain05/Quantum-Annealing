# API Reference

Full interactive documentation (auto-generated by FastAPI, always in sync with the actual code): `http://localhost:8000/docs`.

All endpoints except `/api/health` and `/api/auth/login` require `Authorization: Bearer <token>`.

## Auth
`POST /api/auth/login` - `{email, password}` -> `{access_token, user}`

## Core data
- `GET /api/dashboard` - top-line KPIs
- `GET /api/corridors` - all corridors with current balances and settlement windows
- `GET /api/nostro` - all nostro accounts
- `GET /api/forecasts/{corridor_code}?horizon_days=7` - live-computed forecast

## Optimization
- `POST /api/optimization/run` - builds the QUBO, solves it, persists and returns the full result (see `optimization/engine.py::run_optimization` for the request/response shape; mirrors the source spec's §30 field list: `run_id`, `solver`, `qubo_variables`, `qubo_terms`, `initial_energy`, `final_energy`, `runtime_ms`, `current_liquidity_musd`, `optimized_liquidity_musd`, `capital_released_musd`, `constraint_violations`, `corridor_results`, `convergence_history`)
- `GET /api/optimization/runs` - list past runs
- `GET /api/optimization/runs/{run_id}` - full detail for one run
- `POST /api/optimization/approve` - `{run_id, decision, reason}` - `decision` in `APPROVED | REJECTED | RECALCULATION_REQUESTED`

## QUBO Inspector
- `GET /api/qubo/{run_id}` - rebuilds the exact formulation for a run: variable map, Q matrix, penalty weights, sparsity stats

## Scenarios
- `POST /api/scenarios/run` - `{corridors, confidence_level, demand_delta_pct, volatility_delta_pct, cutoff_delta_hours, label}` - before/after comparison from a genuine re-optimization

## Stress tests
- `POST /api/stress-tests/run` - `{corridors}` (optional) - runs all 8 predefined scenarios
- `GET /api/stress-tests/history` - past stress-test results

## Agent
- `POST /api/agent/ask` - `{question, session_id}` -> `{answer, tools_used, sources, intent_detected}`
- `GET /api/agent/sessions/{session_id}` - conversation history

## Audit
- `GET /api/audit/log` - hash-chained event log
- `GET /api/audit/verify` - recomputes and verifies the entire chain
- `GET /api/audit/approvals` - human approval history

## Health
- `GET /api/health` - database, optimizer, knowledge base, and LLM status
